# HEX-Bridge 固件更新工具

## 用户更新

1. 将 HEX-Bridge 的 **UART0 下载口** 接入 Windows 电脑，关闭占用该串口的串口助手。
2. 双击 `release\HEX-Bridge-Updater-<版本>.exe`，核对窗口显示的内置固件版本。
3. 选择 UART0 对应的 COM 口，点击 **更新固件**，保持连接直到界面提示完成。

本项目台架的下载口为 COM5，COM4 用于 MCP，COM3 用于外设 UART。其他电脑的端口号可能不同，可以拔插下载线并点击「刷新」以辨认。若 Windows 设备管理器未显示下载口，请检查 USB 数据线和 CH340 驱动。

EXE 内置固件和烧录程序，可离线运行。写入失败时窗口会给出原因和临时日志路径。排除连接问题后可在同一窗口重试。

连接阶段显示所选串口。写入时进度条按三个镜像累计的写入位置前进，每段写完后显示校验状态。最终复位流程返回成功才显示 100%。失败时保留已达到的进度，点击「重试更新」后从头开始。

## 开发者发布

在 Windows x64 上准备带 Tk 的 Python 3.11、Python Launcher 和项目使用的 ESP-IDF v6.0.2。默认使用 `D:\project\esp-idf-v6.0.2`，也可以通过 `IDF_PATH` 指定安装目录。

双击 **release.cmd** 即可生成发行文件。脚本为打包依赖创建本地虚拟环境，首次安装需要联网。自动化调用可使用 `release.cmd --quiet` 跳过结束时的按键等待。

发布脚本先执行 `idf.py build`，再从同一构建目录读取项目版本、镜像、偏移和 Flash 参数。它将引导程序、分区表和应用分别嵌入 EXE，自检成功后才将结果移入 `release\`。同版本重新发布会替换同名文件。交付用户时只需复制该 EXE。

发布新版本时先修改工程根目录的 `version.txt`，再运行 `release.cmd`。新 EXE 的文件名和界面版本号都会跟随构建结果。用户手中已有的 EXE 仍包含原来的固件，需要收到新 EXE 后运行更新。

## 写入与验证范围

每次写入前校验三个镜像的 SHA-256。当前配置通过 esptool 以 460800 bps 向 ESP32 分段写入，执行写入校验并通过 RTS 复位。当前工程分区布局下，写入范围避开 NVS、PHY 和 profile 分区。

发布自检会启动 EXE，初始化界面，枚举端口，检查嵌入镜像的哈希，加载 ESP32 下载 stub 并解析应用镜像。也可手动以 `--self-test` 启动 EXE 并检查退出码（0 表示通过）。自检不打开串口。真实设备的写入、复位和启动需要实板验证。
