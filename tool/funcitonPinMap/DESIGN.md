# HEX-Bridge 功能与引脚配置工具

应用和固件共用仓库根目录的 [version.txt](../../version.txt)。窗口标题显示本地应用版本，设备的 GET_INFO 响应报告运行中的固件版本。Profile v1–v5 单独表示配置协议版本。

当前应用支持 Profile v1–v5，依次尝试 v5、v4、v3、v2、v1，只有设备明确拒绝版本或扩展时才降级。UART1 的三种角色、网络接管条件及实板结果见[UART1 的控制与普通串口角色](#uart1-的控制与普通串口角色profile-v4)。

## 阶段 1.6 历史基线（v1 / v2）

| CAN 控制器 | 支持的帧 | 应用中的配置含义 |
|---|---|---|
| 外置 MCP2518FD | 经典 CAN、CAN FD | 阶段 1 的 CAN 开关仅控制此设备。v2 可选 SPI2 或 SPI3（默认 SPI3）；选择主机不会改变 CAN 通道身份，也不会替用户更改物理接线。v1 沿用旧映射，不提供主机选择。 |
| ESP32 片上 TWAI | 仅经典 CAN | 使用 TX/RX 和外部 CAN 收发器，不占 SPI 主机、CS 或 INT。独立启停和通道属于阶段 2.3；阶段 1 不可配置，不能用 MCP2518FD 开关代替。 |

APPLY 发出后若通信断开或没有有效回包，显示“结果未知”及候选 ID，不宣称成功，也不自动重发。GUI 保留草稿并禁止后续写操作，要求等待设备恢复后重新读取阶段及候选 ID。重连相同设备时保留未提交草稿及其来源修订号；身份或能力变化时拒绝套用草稿。设备明确返回的忙、过期等状态仍按原错误显示，不转换成“结果未知”。

`backend.py` 直接导入 `script/hexbridge_profile.py`。CLI 原入口与 GUI 共用版本协商、完整快照编解码、只读元数据核对、v1 JSON 迁移及固定/可编辑/当前/候选占用表。设备操作仍串行运行在单个工作线程，Tk 主线程只更新控件。读取失败保留已有草稿；新设备身份、旧修订号、变更的候选与试用阶段均在任何写请求之前重新核对。

应用先协商 v2，仅在明确收到版本或扩展不支持时回退 v1；通信故障不会当作旧固件。v1 沿用九个映射选择器及九脚引脚条。v2 根据能力位显示 SPI2/SPI3 启用、最大线宽，普通 SPI 业务启用及所属主机、MCP2518FD 所属主机。MCP2518FD 的启用仍由 CAN 功能开关控制。十七个信号选择器分清 UART/DAP、两组总线信号与两个设备的 CS/INT；数据脚切换 Quad 后，候选列表与方向说明随草稿更新，只保留双向候选。线宽能力未宣告 Quad 时仅提供单线。

这些控件每次只修改草稿，不打开外设或写设备。启用主机按最大线宽拥有其总线 GPIO，设备另外拥有 CS/INT；单次单线传输不会释放 Quad 预留脚。当前/设备候选/草稿三状态在参数、信号与常驻引脚条分别展示。保存后当前占用不变，重启试用或回退后重新读取才更新当前视图。应用确认弹窗比较设备已保存候选，包含主机启用、宽度及设备挂载变化，不依赖可能继续修改的本地草稿。

HXB1 v2 默认显示十五个可改配脚，默认 Quad 为十五占用；SPI2 设单线为十三占用，GPIO22/23 空闲；普通 SPI 业务与无其他依赖的 SPI2 一起关闭后为九占用、六空闲。v1 固件仍按旧板表展示九个可改配脚。GPIO15 只供 MCP2518FD.CS；配置完整依赖、争用与保留 CS 的最终判断来自整份 CHECK。

## 使用流程

Windows 中双击 [app.pyw](app.pyw) 启动。该入口使用 Python 的窗口模式，启动时只显示「功能与引脚配置」主窗口。也可从仓库根目录运行 `pythonw tool/funcitonPinMap/app.pyw`。运行环境为 Python 3.10 或更新版本、Tkinter 和 pyserial。选择控制串口和波特率，或输入 `socket://设备IP:9500`，点击读取。连接本工作台时使用 COM3、115200。首次读取只查询设备。

若缺少串口依赖，使用启动应用的同一个 Python 运行 `python -m pip install pyserial`。

## 工作区改版

### 状态变化与冲突反馈

同一设备上编辑草稿、保存候选、切换 UART1 角色或产生冲突时，控件保留原位。状态、差异和诊断使用预先安排的位置，长说明在详情中查看。更新文字和颜色时保持其他分组、选项及操作按钮的位置。用户主动展开详情、切换标签或改变可见信号集合时，仅相应区域调整。

冲突出现时，在功能控制页将所有直接相关的设备名称标红，在引脚配置页同步标红相关信号名称。GPIO 争用同时标出各占用方，无 CS 共用 SPI 主机同时标出两台设备。诊断保留文字说明，便于辨认冲突原因；修正草稿后重新计算，已解决的名称恢复正常颜色，仍有其他冲突的名称继续标红。

验收使用 1024×650 的真实 Tk 窗口，比较状态切换前后的控件坐标、尺寸及主题实际显示的文字颜色。回归覆盖 GPIO 争用、无 CS 的 SPI 设备共用主机、多项冲突分别解除、UART1 切换角色和保存／取消候选。四项新增回归通过，桌面测试共 63 项通过。

顶部保留连接地址、波特率、读取按钮和操作状态。读取成功后显示板型，修订号、协议阶段和候选 ID 收入「设备详情」。有已保存候选时显示「待试用」及试用、取消入口；试用中显示确认入口。若应用结果未知，主界面保留恢复提示，候选 ID 可在详情中核对。引脚全景常驻于连接区与标签栏之间。

| 标签页 | 数据和交互 |
|---|---|
| 功能控制 | 默认列出当前设备可配置的功能及其开关；v2 在此选择 SPI 主机、最大线宽和设备挂载关系。页底可展开完整规划目录中的其余条目。 |
| 引脚配置 | 按草稿中启用的功能列出可改配信号、方向及 GPIO 选择器。候选 GPIO 显示占用方，允许在一次草稿中交换两个信号。页内可展开只读的固定引脚说明和当前、设备候选、草稿占用明细。 |

两个标签页共用同一份草稿。关闭功能立即隐藏其专属信号行，并释放草稿中的对应占用；再次开启时恢复上次选脚，若已被其他功能使用，则标出冲突。隐藏时仍保留完整映射，用于导出、预检和保存。读取、导入或载入候选替换草稿时，同步重算可见行和草稿配色。切换标签无需重新读取。

开关和 SPI 控件直接显示草稿值；当前接线或已保存候选有差异时，才在控件旁补充状态。引脚下拉框内相同的当前与草稿占用方只显示一次。只有设备上存在候选时，信号行才并列展示当前与已保存候选的接线。

SPI 总线信号跟随主机开关和线宽，设备专属信号跟随设备开关。例如 v2 关闭 MCP2518FD 后隐藏其 CS、INT；仍开启的 SPI3 继续显示并占用自己的总线脚。单线模式隐藏 IO2、IO3，切回 Quad 后恢复。UART1 的固定脚始终可在只读明细查看。Wi-Fi、网络服务等没有可分配信号，仅在功能控制页提供开关。

### SPI 独立使用与设备片选（Profile v3）

SPI2 和 SPI3 可分别作为普通 SPI 使用。目标配置允许两者同时收发，MCP2518FD 保持关闭。功能控制页按主机列出总线开关、最大线宽和挂载的普通 SPI 设备；CAN FD 保留独立开关。用户切换其中一路时，另一路的设备、接线及 CAN 开关保持原值。

| 草稿操作 | 引脚配置与占用反馈 |
|---|---|
| 同时启用 SPI2、SPI3，各启用一个普通 SPI 设备，关闭 CAN FD | 两组总线信号分别随线宽显示；两设备可分别选择是否使用 CS。MCP2518FD 的 CS 和 INT 隐藏，GPIO15 仍受板级用途限制。 |
| 为某个普通设备选择「使用 CS」 | 在该设备名下显示 CS 选择器，要求合法输出脚。只有这台设备启用且使用 CS 时才占用该脚。 |
| 将该设备切到「不使用 CS」 | 立即隐藏该行并释放草稿中的片选脚；时钟和数据行保留。设备仍可读写。切回时恢复本次草稿中的上次选脚，若已被其他信号占用则提示冲突。 |
| 关闭普通设备或 CAN FD | 仅释放其专属信号。启用的主机继续预留总线脚。MCP2518FD 启用时必须配置 CS、INT，没有「不使用 CS」选项。 |

无 CS 表示桥不驱动片选线，适用于无需片选或已由硬件固定选中的外设。此类设备按独占总线校验；若同一主机还启用了 MCP2518FD 或另一设备，在相关设备行显示冲突，并指出可迁移的主机。另一条主机仍可独立使用。

**固件兼容。** 应用优先协商最新版本；协商到 v3 或更新版本后按能力提供控件。设备宣告 0x10 时提供普通设备 2，宣告 0x20 时提供设备级「使用 CS」控件。关闭 CS 后隐藏该设备的选脚行，主机独占冲突在相关设备旁显示。当前草稿可恢复刚才的选脚；载入没有历史选脚的无 CS 配置后，重新使用 CS 时优先选择合法的空闲输出脚。v2 继续提供一个必选 CS 的普通设备；v1 沿用原板表。应用验收覆盖双实例启停、独占冲突、两路 CS 释放与恢复、保存候选差异及版本切换。

2026-11-22 使用 ESP-IDF v6.0.2 构建并经 COM5 烧录 HXB1。原 v2 修订 144 的配置与首次 v3 读回逐字段核对通过。实板试用完成后，经 COM3 在桌面应用读回修订 147、已确认、无候选，原 GPIO 映射及设备拓扑恢复。双设备传输记录、复跑命令和电气验证范围见[开发验收记录](../../files/design/function/09-peripheral-delivery-plan.md#阶段-1-后续增量--双普通-spi-通道与设备可选-cs)。

### SPI2 / SPI3 的主从角色（Profile v5）

在「SPI 总线与设备」中，每个控制器占一行，依次显示启用开关、**本机角色**和线宽。角色选项为「主机（本机提供时钟）」和「从机（外部提供时钟）」。普通 SPI 设备及 MCP2518FD 的路由字段称为「所属总线」，取值 SPI2 或 SPI3。SPI2、SPI3 各自选择角色，例如 SPI2 响应外部主机时，SPI3 仍可驱动 CAN FD。SPI Mode 0–3 继续表示时钟极性和相位。

| 本机角色 | 功能控制 | 引脚配置（方向以 HXB1 为准） |
|---|---|---|
| 主机 | 可挂载普通设备和 MCP2518FD。普通设备继续支持独占总线时不用 CS | 单线时 SCLK、MOSI 输出，MISO 输入。普通设备按自己的开关分配 CS 输出；CAN 保留专用 CS、INT |
| 从机 | 本控制器作为一个从机端点，由外部主机发起事务。首版支持单线和外部低有效 CS | SCLK、MOSI、CS 输入，MISO 输出。CS 归本控制器，单独选择；释放主机专用的 IO2、IO3。引脚候选按新方向和板级策略重新计算 |

切换角色先改草稿。若该总线上还有已启用的普通设备或 CAN FD，保留已有挂载，将控制器和全部冲突设备名称标红，提示用户停用设备或迁到另一条已启用的主机总线。若旧接线不适用，例如 SPI3 默认 MISO 在仅输入的 GPIO36，切为从机时将该行标红，提示选择可输出 GPIO。冲突解决后方可保存。角色、差异和诊断沿用固定位置，查看当前接线和已保存候选时分别展示各自的角色及方向。

**固件与协议。** Profile v5 分别保存 SPI2、SPI3 的角色和从机 CS，通过能力位 0x80、0x100 开放各自的从机选择。草稿切换角色后，保存、重启试用并确认才改变硬件。每路从机独占一个控制器，通道 6、7 分别对应 SPI2、SPI3；从 UBCP 预置 1–64 字节，外部主机随后提供时钟和片选。主机可轮询实际接收位数及数据，配置工具负责角色、引脚及候选事务管理。[配置协议](../../files/design/protocol/17-Device-Profile.md) · [SPI 收发协议](../../files/design/protocol/05-SPI.md)

**兼容与验收。** 固件未宣告从机能力时，应用在角色栏显示只读「主机」，将从机选项置灰并说明原因。旧配置升级默认两路均为主机，保留原有启停、接线及设备 CS。新配置包含旧客户端无法表达的从机设置时，固件应拒绝会丢失这些设置的写操作。验收覆盖旧版导入、角色切换与回退、引脚方向、冲突双方标红及解除；实板用外部主机提供时钟和 CS，核对双向字节与实际长度，并验证另一路主机可继续工作。

### UART1 的控制与普通串口角色（Profile v4）

「管理入口」的 **UART1 串口控制** 与「串口与调试」的 **UART1 普通串口** 共用同一个物理串口。应用按草稿角色联动两个复选框。关闭控制只让普通串口变为可选，由用户决定是否启用。UART2 的开关、参数和业务通道独立。

| 草稿中的 UART1 角色 | 管理入口 | 串口与调试 | 试用后的行为 |
|---|---|---|---|
| 串口控制 | 串口控制已勾选 | 普通串口置灰，旁注「由串口控制使用」 | UART1 接收 UBCP 管理报文 |
| 停用 | 两个用途均未选；可重新选串口控制 | 普通串口可勾选 | UART1 保持停用，UART2 可单独工作 |
| 普通串口 | 串口控制未选，旁注「UART1 用于普通收发」 | 普通串口已勾选 | 通过网络管理连接打开 UART1 业务通道，按配置的波特率收发原始字节 |

从普通串口切回控制时，勾选「UART1 串口控制」即在同一草稿中取消普通用途，试用摘要显示「UART1：普通串口 → 串口控制」。编辑或保存期间仍沿用当前角色。仅有 TCP 客户端临时接管管理会话时，UART1 的持久角色保持原值，应用按配置角色判断普通串口是否可选。

**引脚显示。** 两种用途均使用 HXB1 的 TX GPIO4、RX GPIO34。在 UART1 行显示接线，固定引脚明细按当前／候选／草稿标注「串口控制」「普通串口」或「UART1 保留」。两个用途都关闭时，这两脚仍为 UART1 保留。业务波特率、校验位等参数归 UART1 业务通道，和控制连接波特率、UART2 参数分别管理。

**管理入口切换。** 草稿关闭 UART1 控制后，应用在管理入口组显示网络接管条件：启用 Wi-Fi STA、启用 TCP 9500 管理服务，并由固件核对已保存的可用配网参数。普通 TCP 业务不能代替 TCP 9500。试用前提示用户改用网络地址连接，通过 TCP 9500 读回并确认；120 秒内未确认则恢复上一份已确认配置。若恢复 UART1 控制，提示从 UART1 重新连接并确认。

**固件与兼容性。** Profile v4 使用独立的 UART1 普通串口开关。UART2 保留业务通道 1，UART1 使用通道 2；每个已启用的实例独立配置驱动、收发模式及统计。旧配置升级后普通串口默认关闭，原先关闭控制的设备仍保持 UART1 停用。应用根据能力位 0x40 开放普通串口选项；旧固件以灰色显示该项。

**验收。** 覆盖 UART1 单独作为普通串口、UART1/UART2 同时打开且波特率不同、关闭一路后另一路继续收发；核对串口原始数据与 UBCP 管理报文隔离。另测无有效网络管理入口时拒绝保存、角色切换后确认与超时回退、旧固件显示，以及 GPIO4/34 在三种角色下均无法分给其他功能。

HXB1 实板验收（2026-11-22）：原 v3 修订 147 升级后原配置逐项一致。通过 TCP 9500 打开业务通道 2，COM3 实测双向原始字节，包含一帧完整的 UBCP PING。UART2 分别配置为 57600、9600，再执行 CLOSE 或从 Profile 停用，UART1 持续正常收发。业务角色经 TCP 确认，恢复原配置后经 COM3 确认。最终桌面只读核对为 v4、能力 0x7F、修订 156、串口控制、无候选。临时配网已清除，断开串口管理的预检再次报告缺少凭据。本次未接第二个 UART2 物理适配器。[实板验收脚本](../../script/test/test_uart1_role_board.py)

### 引脚全景

当前接线、已保存候选和草稿预览共用下表配色。表中三类 GPIO 色块使用白色编号，详情图例使用对应底色。

| 状态 | 色块底色 | 判定 |
|---|---|---|
| 空闲 | 绿色 `#15803D` | 可分配且没有已启用的信号使用 |
| 使用 | 蓝色 `#1D4ED8` | 由一个已启用的信号使用 |
| 冲突 | 红色 `#B91C1C` | 多个信号争用同一引脚，编号旁加「!」 |

顶部显示视图名称、按编号排列的 GPIO 色块和「查看详情」入口。展开全部引脚后，深灰表示固定保留，浅灰表示未引出或无对应 GPIO。悬停或键盘聚焦可读出状态，点击或按回车可查用途与方向限制。相关选脚行显示冲突原因；冲突解决后按该引脚的新状态重新着色。

「查看详情」集中提供视图切换、颜色图例、按可见范围统计的数量、固定用途和「显示全部引脚」开关。展开全部后可查看 GPIO0–39。切换视图或标签时保留所选范围。编号顺序不代表排针位置。

首次读取显示「当前接线」。修改功能、线宽、挂载或引脚，或通过导入、载入候选更新草稿时，顶部立即切至「草稿预览」并重新着色。仅切换标签时保留视图。用户可在详情中切回「当前接线」核对实物；下一次编辑再自动预览。仅设备报告有效候选时提供「已保存候选」视图。视图切换读取本地快照；保存后的当前接线仍取运行映射，试用或回退后重新读取才更新。

|---|---|---:|
| Flash、PSRAM | 6–11、16–17 | 8 |
| UART0 下载及日志、UART1 固定接线 | 1、3、4、34 | 4 |
| EEPROM | 12、33 | 2 |

| 业务 | 当前占用（GPIO → 信号） | 占用数量 |
|---|---|---:|
| CAN | 13 → MOSI、14 → SCK、15 → CS、36 → MISO、39 → INT | 5 |
| DAP | 25 → SWCLK、26 → SWDIO | 2 |

### 改版验收场景

1. 读取上表 v1 样本后，「当前接线」显示九个蓝色编号。在「功能控制」关闭 DAPLink，当页顶部立即显示「草稿预览」，GPIO25、26 变绿。切到「引脚配置」后 SWCLK、SWDIO 两行消失；将 UART2.TX 从 GPIO32 改为 GPIO25，行内可核对新接线，GPIO25 变蓝、GPIO32 变绿。在详情切回「当前接线」仍见九个蓝色编号。
2. 接上例重新开启 DAPLink，顶部自动回到「草稿预览」。SWCLK 恢复到 GPIO25，该脚变红并出现「!」，两条选脚行均指出争用方。将 UART2.TX 移回 GPIO32 后，GPIO25 恢复蓝色，冲突图标和行内提示消失。
3. 读取 v2 默认配置，关闭普通 SPI 业务，仅其 CS 行消失；继续关闭无其他设备挂载的 SPI2 后，其总线行消失，草稿显示九蓝、六绿。切换标签时保留草稿、顶部模式和显示范围。
4. 在阶段 1 固件上，「计划支持」初始折叠，展开可见灰色的 TWAI、I2C0/1、通用 GPIO、LEDC、MCPWM、PCNT、以太网，均不可选脚。关闭 UART2 后，其开关仍在可操作列表，再次开启即可恢复原 TX/RX 映射。
5. 默认顶部没有状态计数；打开「查看详情」可查图例和统计。展开全部引脚后，固定和不可用编号分别呈深灰、浅灰。聚焦或打开引脚详情可查询 GPIO35 仅可输入、GPIO15 仅供 MCP2518FD.CS 等限制。
6. 无候选时，视图列表只提供当前接线和草稿预览。保存候选并读回后出现「已保存候选」视图及待试用操作；修订号和候选 ID 可在设备详情中核对。

本轮验证覆盖以上六个场景。桌面工具与服务回归 43 项通过，共享协议示例 7 项通过，CLI 与主机编译的固件处理器集成回归 13 项通过。1024×650 实际 Tk 窗口已检查功能页、GPIO25 改线和冲突提示。COM3 只读核对 HXB1 v2 修订 144，设备处于已确认阶段，无候选；界面显示 15 个已分配业务脚，展开后另有 17 个固定脚和 8 个不可用编号。切页、展开详情和切换视图均使用首次读取的快照。保存、试用及回退在主机回归中验证。

### 目标设计：按设备能力管理可选外设

扩展版界面按[外设功能目录](../../files/design/function/08-device-profile.md)展示实例及通道。SPI2、SPI3 分别启停，可为通用 SPI 设备和 MCP2518FD 选择所属主机；当前、候选和草稿均展示主机、共享信号与专属 CS/INT。I2C0/1、UART1/2、片上 TWAI 和外接 CAN FD 独立列出。GPIO、16 路 LEDC、MCPWM、8 路 PCNT、以太网按设备宣告的资源展开；通道按需启用。始终保留 UART1 或 Wi-Fi TCP 9500 管理入口。旧固件继续显示 v1 的实际能力。

外接 SPI2 的功能开关和六条信号映射纳入设备配置。默认接线为 SCLK=18、IO0/MOSI=19、IO1/MISO=21、IO2/WP=22、IO3/HD=23、CS=27。按总线配置的最大线宽显示占用：仅单线时释放 IO2/IO3，MISO 可使用输入脚；允许 Quad 时四条数据线均须双向，即使暂时只做单线传输也保留 IO2/IO3。默认接线且原九个业务信号全开时，两种配置分别显示 13 和 15 个已占用脚。

沿用其他板级保护时，34 个芯片 GPIO 扣除本板不可用的 37、38，再扣 17 个固定脚，得到 **15 个可改配 GPIO**：13、14、15、18、19、21、22、23、25、26、27、32、35、36、39。沿用默认接线、九个原信号启用且 SPI2 占六线时，15 个已占用、0 个空闲；关闭普通 SPI 业务及无其他依赖的 SPI2 后，9 个已占用、6 个空闲。全景始终展示这 15 脚，按运行、候选或草稿分别着色。

兼容要求：现有 v1 报文只有九个映射槽位，板表把上述六脚标为 SPI2 固定用途。扩展固件需描述双 SPI 主机、启用设备和信号占用，驱动的初始化、CS 校验、释放和重新打开路径均须使用有效映射。连接旧固件时沿用其描述。版本迁移见[设备配置协议](../../files/design/protocol/17-Device-Profile.md)。

### ESP32-D0WD-V3 对外功能盘点

| 片上资源 | 芯片能力 | HXB1 使用情况或约束 |
|---|---|---|
| 通用 GPIO、RTC GPIO | 数字输入输出、中断、部分引脚支持 RTC 唤醒 | 通用 GPIO 读写可作为独立业务；区分仅输入、开漏和保留脚 |
| SPI | SPI0/1 用于存储子系统；SPI2、SPI3 可作通用 SPI | SPI2 外接扩展；SPI3 接 MCP2518FD，已计入 CAN 用脚 |
| I²C | 2 个控制器 | 板载 EEPROM 默认 SCL=12、SDA=33。新增外接总线可在合法开漏 GPIO 选脚，也可评估共享总线；GPIO12 涉及启动电平 |
| UART | 3 个控制器 | UART0 下载日志；UART1 控制或普通串口；UART2 可改配，硬件流控另计信号 |
| TWAI | 1 个经典 CAN 控制器 | 可另行设计 TX/RX 及外接收发器；当前外接 MCP2518FD 提供经典 CAN 与 CAN FD |
| LEDC、MCPWM | LEDC 最多 16 路 PWM；MCPWM 两组，每组 3 对输出 | 普通 PWM 与互补 PWM、死区、捕获等分别建模 |
| ADC、DAC、触摸 | 两个 12 位 ADC，最多 18 个输入通道；2 路 8 位 DAC；10 个触摸通道 | 仅列芯片支持该功能的脚。DAC 在 GPIO25/26；ADC2 采集受 Wi-Fi 使用约束 |
| RMT、PCNT | RMT 8 通道；脉冲计数器 8 单元 | 波形收发、脉宽测量、计数或正交编码器 |
| I²S | 2 个控制器 | 数字音频；并行摄像头或 LCD 等模式会共享底层资源 |
| SD/MMC、SDIO | SD/MMC/SDIO 主机；SDIO/SPI 从机 | 需要核对固定信号组、上拉和现有存储/启动占用 |
| 以太网 MAC | 10/100 Mbps | 外部 PHY、参考时钟和相应接线是使用前提 |
| JTAG | 芯片自身调试接口 | 与 HXB1 通过 GPIO 实现的对外 DAP/SWD 区分 |
| Wi-Fi、蓝牙、内部资源 | 2.4 GHz Wi-Fi、经典蓝牙/BLE；定时器、看门狗、RTC、ULP、随机数及加密等 | 无外接信号时不计入 GPIO 占用；原版 ESP32 无原生 USB OTG |

已纳入分期规划的功能以外设功能目录为准。ADC、DAC、触摸、RMT、I²S 和 SD 等仍属芯片能力参考。通道数是芯片资源上限；新增外设需与现有功能竞争合法 GPIO。依据：[乐鑫 ESP32 数据手册第 2、4 章](https://documentation.espressif.com/esp32_datasheet_en.html)、[当前 SPI2 驱动](../../main/modules/mod_spi.c)、[板级常量](../../main/hex_config.h)。

## 配置事务

草稿始于当前映射，支持载入已暂存的候选。预检和保存提交完整映射与原修订号。保存后重新读取，当前占用保持原状。取消、试用重启和确认使用最近快照中的候选 ID，并核对设备阶段。应用前提示重启和 120 秒确认期限；重启后重新读取设备，进入试用才能确认。超时或复位回退以设备读数为准。错误显示固件原因并保留可修正的草稿。

## 实现与验证

本次 v4 验收通过 59 项桌面回归、10 项 UART1 配置服务测试、14 项配置示例测试，以及 18 项 CLI 对真实固件处理器的主机测试。1024×650 窗口已检查分组、开关和滚动范围。HXB1 的 COM3 只读验收经实际 Tk 按钮触发，核对两个标签页、当前角色、候选状态和草稿状态。

采用 Python 标准库 Tkinter/ttk。直接导入共享 `script/hexbridge_profile.py` 的设备请求、映射编码、JSON 校验和三表生成函数，协商 UBCP 0x08 的 v1/v2 配置版本。设备 I/O 在工作线程串行执行，Tk 主线程负责呈现和交互，同一时间只允许一项设备操作。程序按自身路径定位仓库模块，支持从其他工作目录启动。

测试使用模拟设备验证编辑、预览、非法导入、修订冲突、候选事务和错误恢复。运行 Tk 窗口验证控件和操作入口。在已连接的 HXB1 上只读核对板型、阶段和三张表。

在有桌面环境的电脑上，从仓库根目录执行 `python tool/funcitonPinMap/test_app.py` 可复跑自动测试。测试使用内存中的设备替身和真实 Tk 控件，不占用串口。
