# 外部 SPI 固件模块设计

> 本文描述 `mod_spi` 如何把 UBCP SPI 命令映射到 ESP-IDF 主机和从机驱动。命令载荷和主机可见行为以 [SPI 协议定义](../protocol/05-SPI.md) 为准。

## 1. 目标与边界

`mod_spi` 在设备配置 v3 下提供两个普通 SPI 通道，每个启用的设备可选择 SPI2 或 SPI3。两设备分别保存句柄、打开状态和传输参数，共用分发锁及缓冲区。MCP2518FD 独立选主机和启停。

现有普通 SPI 设备沿用通道 `UBCP_CH_SPI_EXT1 (4)`，OPEN 校验生效配置中的 CS GPIO。支持单线 8/16 位与 Quad 8 位事务。

### 双普通 SPI 与可选 CS

- 每个普通业务实例具有稳定的可发现通道。按通道选择设备句柄、打开状态、时钟、线宽、片选方式和持锁状态。两主机各挂一个普通设备时允许同时打开；关闭、重配或传输失败只清理对应实例。继续通过共享总线管理器管理主机和事务所有权。
- 普通设备选择无 CS 时，OPEN、CONFIG、传输、CLOSE、STOP 和失败回滚均跳过 CS 的位掩码运算、GPIO 配置、电平切换及复位。事务仍按所属主机仲裁。无 CS 模式下拒绝手动片选控制。当前驱动中的 `spics_io_num = -1` 表示 CS 由软件 GPIO 驱动，仍会操作实际引脚。
- 配置校验按启用设备检查独立片选、总线依赖及方向。无 CS 的普通设备独占其主机；即使软件串行化，始终选中的外设仍可能响应同总线其他设备的时钟。MCP2518FD 始终校验其 CS/INT，GPIO15 仅供其 CS。
- 主机回归分别验证两个通道的打开、不同配置、交替传输、关闭一路和失败清理；断言无 CS 实例的全生命周期对片选 GPIO 零访问。实板在 CAN FD 关闭时对两组独立接线分别验证收发，并用逻辑分析仪检查无 CS 传输及另一实例的 CS 时序。

Profile v5 的从机模式见第 7 节。ESP-IDF 的从设备驱动需要应用预先排队事务；外部主设备拉低 CS 并送出时钟后才完成传输，因此软件不能保证在一次事务中途才生成回复。驱动提供事务队列和完成结果接口，需以队列为固件架构基础。

## 2. 软件结构与资源

| 资源 | 设计 |
|:---|:---|
| 模块入口 | `mod_spi_get()` 返回 `hex_module_t`，命令范围 `0x20-0x2F` |
| 总线 | 共享总线管理器按生效主机和线宽初始化，设备按所属主机引用总线 |
| 设备句柄 | `spi_bus_add_device()` 按当前 mode、时钟、位序和 Quad 能力创建；软件控制 CS，驱动设备的 `spics_io_num=-1` |
| 互斥 | FreeRTOS mutex 保护设备句柄、配置、CS 操作和同步传输；取锁超时返回 `ERR_BUSY` |
| 缓冲区 | 静态 TX/RX 缓冲区各 2045 字节，静态响应缓冲区为 UBCP 最大载荷，避免事务中动态分配 |
| 拓扑 | 初始化后按启用实例注册通道 4、5，设备类型为 SPI |

普通设备默认接 SPI2，SCLK=18、IO0=19、IO1=21、IO2=22、IO3=23、设备 CS=27。v2 启动时使用已确认或试用配置的路由与最大线宽。

## 3. 初始化与生命周期

### 模块初始化

1. 创建模块 mutex。
2. 取得生效配置指定的 SPI 主机，引用其时钟与数据线。
3. 全部启用实例取得主机引用后注册各自的 UBCP 通道。
4. 上层停止模块时，若设备已打开则先释放 CS、移除设备，再归还所属总线引用。

总线初始化失败时模块初始化返回错误；通道注册只在总线成功初始化后进行。

### OPEN / CLOSE

当前 OPEN 校验设备配置的 CS GPIO 和极性，预置非有效电平后启用输出，再以默认参数添加设备（Mode 0、1 MHz、MSB、8 位、自动 CS、单线）。设备添加成功后进入打开状态。重复 OPEN 返回 `ERR_ALREADY_OPEN`。

CLOSE 在 mutex 保护下将 CS 置为非有效电平、移除设备并清除打开状态，最后释放 CS GPIO 配置。关闭态 CLOSE 返回 `ERR_NOT_OPEN`。模块 stop 执行同样的资源清理，并额外释放 SPI2 总线。

### CONFIG

CONFIG 校验 9 字节载荷、mode、时钟范围、位序、字宽、CS 模式和线宽。Quad 与 16 位字宽组合不支持。更新时先释放可能保持的手动 CS，移除旧设备句柄，再按新参数添加设备；如添加失败则恢复旧参数并尝试重建旧设备。恢复也失败时设备转为关闭态。

ESP-IDF 设备配置启用 LSB flag（如选择 LSB）及 Quad half-duplex flag（Quad 模式）。CS 由 GPIO 软件控制，因此 CS 极性可配置，且支持跨 UBCP 请求保持。

## 4. 命令处理与事务映射

消息总线将 SPI 命令交给 `spi_handle()`。模块先检查通道号，再分发 OPEN、CLOSE、CONFIG、TRANSFER、WRITE、READ 或 CS_CONTROL；未知命令返回 `ERR_NOT_SUPPORT`。数据命令检查载荷长度、N 值、最大传输长度及 16 位偶数长度要求。

| UBCP 命令 | SPI 驱动操作 | 成功响应 |
|:---|:---|:---|
| `SPI_TRANSFER` | 单线事务，TX/RX 均为 N 字节 | `Status, RxLen:u16, RxData[N]` |
| `SPI_WRITE` | TX N 字节；单线丢弃 RX，Quad 以 QIO 半双工发送 | `Status, ActualLen:u16` |
| `SPI_READ` | 单线发送 FillByte 并接收；Quad 使用纯输入 QIO 阶段 | `Status, RxLen:u16, RxData[N]` |
| `SPI_CS_CONTROL` | 手动 CS 模式下设置本设备已配置片选脚的有效／非有效电平 | `Status` |

自动 CS 模式由模块在事务前后切换 GPIO；手动模式下数据事务不操作 CS，由主机显式控制。CONFIG 和 CLOSE 都会释放 CS。设备事务通过 `spi_device_transmit()` 同步完成，模块 mutex 确保同一时刻只有一条 SPI 操作访问设备状态和缓冲区。

## 5. 响应与错误处理

- 成功数据响应在静态响应缓冲区中组装，长度字段使用大端序；READ/TRANSFER 数据按 SPI 接收字节原样返回。
- 参数错误、错误通道、未打开、重复打开和忙等待超时使用对应 UBCP 通用状态码。
- 不支持的操作使用 `ERR_NOT_SUPPORT`；SPI 传输失败使用 `ERR_SPI_TRANSFER`；OPEN/CONFIG/CLOSE 驱动层失败映射为 `ERR_HAL_FAIL`。
- 错误响应仅含一个 Status 字节；成功响应长度由对应命令定义。
- 传输失败时自动 CS 释放；手动 CS 保持主机设置的状态，主机应 Deassert 或 CLOSE。

## 7. SPI 从设备模式（Profile v5）

### 7.1 模式和生命周期

控制器按试用重启后的生效角色初始化，角色在本次启动期间固定。SPI3 已支持普通 SPI 主机业务。搭建主从自测夹具时，先核对两主机及 MCP2518FD 的实际挂载和接线。

从设备角色由外部主设备提供 SCLK、CS、MOSI；ESP32 提供 MISO。ESP32 不决定外部事务开始时间，也不能主动产生时钟。因此命令接口必须是异步队列语义，而不能照搬现有 `SPI_TRANSFER` 的同步主设备语义。

### 7.2 首版实现契约（Profile v5）

SPI2、SPI3 各自选择主机或从机。一条启用的控制器只有一个驱动所有者。主机继续使用现有总线管理器；从机通过 ESP-IDF SPI Slave 驱动独占该控制器，挂载于同一控制器的普通主机设备和 MCP2518FD 必须关闭或改接另一主机。初始化失败沿用 Profile 试用回退。驱动分发、能力和拓扑均须识别仅启用从机的配置。

首版从机固定单线、Mode 0、MSB 优先、低有效外部 CS，使用非 DMA 的单笔 1–64 字节缓冲。SCLK、MOSI、CS 是输入，MISO 是输出。UBCP 预置一笔事务后由外部主机提供时钟，按实际接收位数取回数据。轮询零等待，已排队的事务由驱动持有缓冲；完成读取后方可复用。上一管理会话的收发缓冲不得作为新会话数据交付。没有外接 READY 的首版适用于能和 UBCP 调用方协调开始时刻的外部主机，预置顺序和就绪判定见协议。

验收涵盖双主机兼容、一主一从、双从机、总线独占、方向检查及初始化失败回退。主机测试模拟外部时钟、短传输及繁忙状态，电气验收需外部 SPI 主机驱动有效 CS、SCLK 和 MOSI 并采样 MISO。
