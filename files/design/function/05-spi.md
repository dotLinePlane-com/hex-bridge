# 05. SPI 外部扩展功能

> **状态**：SPI 主设备模式固件已实现；SPI 从设备模式列入后续规划，尚未定义线上协议或实现。
> **命令码范围**：`0x20-0x2F`；外部 SPI 通道：`UBCP_CH_SPI_EXT1 = 4`

---

## 1. 功能描述

HEX-Bridge 通过 ESP32 的 SPI2 主机接口控制一个外接 SPI 从设备。主机可配置时钟模式、时钟频率、位序、字宽、片选策略和数据线宽度，并执行单线全双工、单线读写或 Quad SPI 半双工读写。

本功能面向通用 SPI 总线事务，不解释外设内部的命令、寄存器或地址含义；这些内容由上位机按外设数据手册组织成传输字节。

### 总线、设备与通道的关系

- **SPI 控制器/总线**：本产品当前对外提供一条 SPI2 主设备总线，共享 SCLK、IO0–IO3 数据线。
- **SPI 从设备**：挂在总线上的外设，由片选（CS）区分。同一条总线理论上可以连接多个从设备，但每个设备需要独立 CS，且其模式、频率、位序等参数可能不同。
- **UBCP 通道**：主机命令寻址的逻辑设备标识。系统 `GET_TOPOLOGY` 用于发现固件静态提供的通道，不是用户修改硬件资源数量的配置命令。

### 当前设备管理范围

当前板级设计只分配一个外部 SPI CS（GPIO27），固件只注册 `UBCP_CH_SPI_EXT1 = 4` 并只维护一个 SPI 设备实例。因此当前可用外设数量上限为 **1**，主机可通过该通道的 OPEN/CLOSE 决定它是否处于打开状态。主机不能通过 `SPI_CONFIG` 或系统 `SET_CONFIG` 配置设备数量；`SPI_CONFIG` 只修改已打开设备的总线参数。`GET_TOPOLOGY` 返回当前固件提供的通道清单。

SPI 协议的 `SPI_OPEN` 参数包含 CS 引脚，但当前固件仅接受 GPIO27；该字段不意味着主机可任意选择引脚或创建额外设备。其他 CS 引脚尚未分配到原理图，也没有对应的通道 ID 和设备实例管理实现。

## 2. 子功能

| 子功能 | 命令码 | 说明 |
|:---|:---|:---|
| 设备生命周期 | `0x20 SPI_OPEN`, `0x21 SPI_CLOSE` | 打开或关闭通道 4 对应的 SPI2 外设连接；当前只允许一个设备实例 |
| 总线配置 | `0x22 SPI_CONFIG` | 配置 SPI Mode 0–3、10 kHz–40 MHz、MSB/LSB、8/16 位、自动/手动 CS、单线/Quad |
| 事务收发 | `0x23 SPI_TRANSFER`, `0x24 SPI_WRITE`, `0x25 SPI_READ` | 单线全双工；单线或 Quad 写；单线填充读或 Quad 四线读。单次数据长度 1–2045 字节 |
| 片选控制 | `0x26 SPI_CS_CONTROL` | 手动 CS 模式下显式 Assert/Deassert，可跨多个 UBCP 请求保持片选 |
| 预留 | `0x27-0x2F` | 保留给后续 SPI 扩展 |

### 多设备扩展原则（后续规划）

若产品后续要支持多个 SPI 从设备，应先确定板级可用的独立 CS 引脚数量，并为每个 CS 分配静态 UBCP 通道 ID；各通道拥有独立 OPEN/CLOSE 状态和设备参数，但共享 SPI2 总线并由固件串行化事务。主机可选择打开其中一个或多个已提供的通道，实际并发打开上限由板级 CS 资源和固件实例容量决定。

这属于基于固定硬件上限的“选择启用数量”，不能让配置凭空创建额外 SPI 控制器或 CS 引脚。实现该扩展前，还需更新原理图/引脚表、`GET_TOPOLOGY` 通道注册、SPI 命令路由和多实例资源管理。当前 GPIO 规划只有一个外部 SPI CS，因此**当前版本没有可由用户设置的 SPI 设备数量**。

Quad 模式使用 IO0–IO3 四条双向数据线，只支持 8 位字宽及半双工数据阶段，不支持 Dual/Octal、全双工 Quad、DDR、自动命令/地址阶段或 dummy cycle 配置。需要命令/地址后接数据的外设，可在手动 CS 下分多个 WRITE/READ 请求完成；所有阶段须采用同一线宽。

### 后续规划：SPI 从设备模式

SPI 从设备（Target）模式指 ESP32 接受外部 SPI 主设备提供的时钟和 CS，并按已准备好的发送缓冲区返回数据，同时接收外部主设备发送的数据。该模式**不是当前 `0x20-0x2F` 协议已支持的功能**，与现有 SPI 主设备模式互斥，后续需单独完成需求、引脚、命令和测试设计。

从设备模式需优先定义：如何预装发送数据、外部主设备如何获知 ESP32 已就绪、每个 CS 周期的帧边界/长度、接收数据如何通知 UBCP 主机、队列深度和溢出策略、超时与复位行为。由于 CPU 驱动 SPI 从设备不能在外部主设备任意发起事务时临时构造响应，建议采用“预置 TX/RX 缓冲区 + READY 握手 GPIO + 队列/完成事件”的方案评估。READY 引脚尚未分配，需在引脚表中确定后再固化协议。

现阶段没有专用外部从设备时，可先用 SPI2 从设备与 SPI3 主设备组成板内自测夹具（测试固件停用 CAN 模块，并用跳线连接信号）；也可使用第二块 MCU 或可编程 SPI 主机。自测夹具验证软件和收发逻辑，最终仍需真实外部主设备验证电气时序。

## 3. 硬件依赖

- **控制器**：ESP32 `SPI2_HOST`，作为主机；板载 MCP2518FD 使用独立 SPI3，不占用此通道。
- **引脚**：SCLK=GPIO18、IO0/MOSI=GPIO19、IO1/MISO=GPIO21、IO2=GPIO22、IO3=GPIO23、CS=GPIO27。
- **引脚映射固定**：固件通过 GPIO Matrix 路由；UBCP 不提供运行时重映射。GPIO27 分配给 SPI CS 后，不再同时提供 SWD nRESET。
- **电气**：SPI IO 电平为 3.3 V。外接设备需共地并满足 ESP32 电平要求；CS 空闲电平按极性配置，Quad IO 上下拉按从设备要求设计。可用最高时钟受器件时序及板级信号完整性限制。

完整引脚和板级约束见 [ESP32 引脚规划](../sch/esp32-pinout-design.md)。

## 4. 使用约定

1. 使用通道 `0x04` 调用 `SPI_OPEN`，CS 引脚参数固定为 GPIO27，并选择有效电平。
2. 调用 `SPI_CONFIG` 设置所需总线参数。默认值为 Mode 0、1 MHz、MSB、8 位、自动 CS、单线。
3. 每次最多传输 2045 字节；多字节协议字段采用 UBCP 大端序，SPI 数据本身按提供的原始字节序列发送。
4. 自动 CS 每条数据命令独立拉低/拉高（或按配置极性切换）。若外设要求命令与数据处于同一 CS 周期，使用手动 CS 包围多次数据命令。
5. 使用完毕调用 `SPI_CLOSE`。关闭和重新配置会释放手动保持中的 CS。

命令载荷、响应、错误码和边界条件以 [SPI 协议定义](../protocol/05-SPI.md) 为准。
