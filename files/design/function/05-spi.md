# 05. SPI 外部扩展功能

> **状态**：Profile v1–v4 提供主机模式。Profile v5 允许 SPI2、SPI3 分别选择本机角色。
> **命令码范围**：`0x20-0x2F`。普通设备通道为 4 和 5（第二设备需 Profile v3）。

---

## 1. 功能描述

固件通过设备配置 v2 支持启停 SPI2、SPI3，为外接 SPI 业务和 MCP2518FD 分别选择主机；总线共享、片选归属及分期验收见[设备功能与引脚配置](08-device-profile.md)。主机回归已覆盖驱动生命周期与仲裁；迁移接线的电气验收仍需实板。

HEX-Bridge 通过选定的 SPI2 或 SPI3 主机接口控制一个外接 SPI 从设备。主机可配置时钟模式、时钟频率、位序、字宽、片选策略和数据线宽度，并执行单线全双工、单线读写或 Quad SPI 半双工读写。

本功能面向通用 SPI 总线事务，不解释外设内部的命令、寄存器或地址含义；这些内容由上位机按外设数据手册组织成传输字节。

### 总线、设备与通道的关系

- **SPI 控制器/总线**：SPI2、SPI3 分别管理一份总线映射，外接 SPI 和 MCP2518FD 可选择同一主机，共享 SCLK、IO0–IO3。每设备保留独立时钟和 CS，由驱动串行化事务。
- **SPI 从设备**：挂在总线上的外设，由片选（CS）区分。同一条总线理论上可以连接多个从设备，但每个设备需要独立 CS，且其模式、频率、位序等参数可能不同。
- **UBCP 通道**：主机命令寻址的逻辑设备标识。系统 `GET_TOPOLOGY` 用于发现固件静态提供的通道，不是用户修改硬件资源数量的配置命令。

### 当前设备管理范围

Profile v3 支持两个独立寻址的普通 SPI 设备，允许 CAN FD 关闭时同时使用 SPI2 和 SPI3。普通设备可使用独立 CS，或在独占总线上无 CS 收发。MCP2518FD 保留专属 CS 和 INT。主机通过拓扑发现已启用的通道 4、5。[固件模块设计](../firmware/09-SPI-Module.md)

#### v2 兼容基线

外接 SPI 设备分配一个 CS（默认 GPIO27），固件只注册 `UBCP_CH_SPI_EXT1 = 4` 并只维护一个 SPI 设备实例。因此当前可用外设数量上限为 **1**，主机可通过该通道的 OPEN/CLOSE 决定它是否处于打开状态。主机不能通过 `SPI_CONFIG` 或系统 `SET_CONFIG` 配置设备数量；`SPI_CONFIG` 只修改已打开设备的总线参数。`GET_TOPOLOGY` 返回当前固件提供的通道清单。

SPI 协议的 `SPI_OPEN` 参数包含 CS 引脚，仅接受生效设备配置指定的外接 CS（默认 GPIO27）；该字段不能创建额外设备或操作 CAN 专属 CS。GPIO15 仅供 MCP2518FD.CS。关闭外接业务后不注册通道4；已启用主机仍预留其配置引脚，只有无依赖且关闭主机后才释放总线资源。

共享主机且 CAN 启用时，SPI_CONFIG 拒绝手动 CS 模式并返回 ERR_NOT_SUPPORT，防止跨请求持有主机导致分发器死锁。独占主机的手动 CS 可跨请求保持，配置、关闭和停止会释放它。总线最大线宽为单线时，请求 Quad 在访问 GPIO 前被拒绝；Quad 主机不会因单次单线传输释放 IO2/IO3。

驱动主机回归：在 VS 开发环境运行 `python script/test/test_spi_host.py`，直接编译真实 SPI 模块、MCP2518FD 驱动和共享总线管理器，对总线引用、事务仲裁、片选、单线/Quad 限制与失败释放作断言。实板冒烟入口为 `python script/test/test_spi_smoke.py --mcp COM4 --cs 27 --max-width 1`，参数须匹配生效配置和已确认接线；Quad 总线改为 `--max-width 4`。默认只验命令、状态、长度和限宽，不以任意读回值认定外设或电气时序通过。只有已确认 MOSI/MISO 回环、且 CAN 位于其他主机时才加 `--loopback`。完整板端 CLI 配置验收入口为 `script/test/test_profile_board.py`；实际端口与能力证据见交付记录。

CAN 启用的试用启动还会对 MCP2518FD 执行 RESET、等待振荡器就绪、进入内部回环并回读、恢复配置模式并回读，证明新 SPI/CS 映射可访问芯片。两次模式转换同时验证 MOSI 写入和 MISO 读回，不发送 CAN 帧，不依赖 CAN 对端 ACK 或 CAN_OPEN。任一步失败都会标记驱动失败并回退，不允许 CONFIRM。已确认配置的日常启动不执行该探测或额外复位。主机模型覆盖正常通信、读回全零、全 FF 和忽略写入的失败情况；实际移线仍须试用验证。

ESP32 固定分配 SPI2→DMA1、SPI3→DMA2，避免启停另一主机改变 DMA 分配。在 HXB1 原 CAN 接线的实板 A/B 中，AUTO 分配使独占 SPI3 获 DMA1，出现 MCP 读回 0xFE 并误触发试用回退；仅保留 SPI2 主机时正常，固定 DMA2 后关闭 SPI2 的试用可正常确认。增加启动延时不能解决该问题。主机回归同时断言两个 SPI 实例的 DMA 参数。

## 2. 子功能

| 子功能 | 命令码 | 说明 |
|:---|:---|:---|
| 设备生命周期 | `0x20 SPI_OPEN`, `0x21 SPI_CLOSE` | 打开或关闭通道 4 对应的 SPI2 外设连接；当前只允许一个设备实例 |
| 总线配置 | `0x22 SPI_CONFIG` | 配置 SPI Mode 0–3、10 kHz–40 MHz、MSB/LSB、8/16 位、自动/手动 CS、单线/Quad |
| 事务收发 | `0x23 SPI_TRANSFER`, `0x24 SPI_WRITE`, `0x25 SPI_READ` | 单线全双工；单线或 Quad 写；单线填充读或 Quad 四线读。单次数据长度 1–2045 字节 |
| 片选控制 | `0x26 SPI_CS_CONTROL` | 手动 CS 模式下显式 Assert/Deassert，可跨多个 UBCP 请求保持片选 |
| 从机收发 | `0x27 / 0x28` | 预置应答和领取实际收到的数据 |
| 预留 | `0x29-0x2F` | 后续扩展 |

### 同一总线上的设备

普通主机设备 1、2 按各自的 CS 策略和通道（4、5）启用；启用无 CS 的设备时，它独占所属主机。MCP2518FD 需要主机和专用 CS。控制器切换到从机后，同一控制器上不能继续挂载这些主机业务设备。

Quad 模式使用 IO0–IO3 四条双向数据线，只支持 8 位字宽及半双工数据阶段，不支持 Dual/Octal、全双工 Quad、DDR、自动命令/地址阶段或 dummy cycle 配置。需要命令/地址后接数据的外设，可在手动 CS 下分多个 WRITE/READ 请求完成；所有阶段须采用同一线宽。

### 本机作为 SPI 从机

开启从机时，外部主机提供低有效 CS、SCLK 和 MOSI，桥通过 MISO 返回已预置的数据。SPI2 从机用通道 6，SPI3 从机用通道 7。先预置 1–64 字节，成功后再让外部主机发起一次 Mode 0、MSB 优先、单线传输。轮询 FETCH 可获得实际位数及数据。每路一个事务槽，满槽返回 BUSY。具体边界见[SPI 从机端点](../protocol/05-SPI.md#spi-从机端点profile-v5)。

## 3. 硬件依赖

- **控制器**：外接业务默认使用 SPI2，MCP2518FD 默认使用 SPI3；两者可通过设备配置分别选择主机。
- **默认引脚**：SCLK=GPIO18、IO0/MOSI=GPIO19、IO1/MISO=GPIO21、IO2=GPIO22、IO3=GPIO23、CS=GPIO27。
- **引脚映射**：设备配置经试用重启后生效，固件通过 GPIO Matrix 路由。GPIO27 分配给 SPI CS 后，不再同时提供 SWD nRESET。
- **电气**：SPI IO 电平为 3.3 V。外接设备需共地并满足 ESP32 电平要求；CS 空闲电平按极性配置，Quad IO 上下拉按从设备要求设计。可用最高时钟受器件时序及板级信号完整性限制。

完整引脚和板级约束见 [ESP32 引脚规划](../../sch/esp32-pinout-design.md)。

## 4. 使用约定

1. 使用通道 `0x04` 调用 `SPI_OPEN`，CS 引脚参数取自当前外接设备映射，默认 GPIO27，并选择有效电平。
2. 调用 `SPI_CONFIG` 设置所需总线参数。默认值为 Mode 0、1 MHz、MSB、8 位、自动 CS、单线。
3. 每次最多传输 2045 字节；多字节协议字段采用 UBCP 大端序，SPI 数据本身按提供的原始字节序列发送。
4. 自动 CS 每条数据命令独立拉低/拉高（或按配置极性切换）。若外设要求命令与数据处于同一 CS 周期，使用手动 CS 包围多次数据命令。
5. 使用完毕调用 `SPI_CLOSE`。关闭和重新配置会释放手动保持中的 CS。

命令载荷、响应、错误码和边界条件以 [SPI 协议定义](../protocol/05-SPI.md) 为准。
