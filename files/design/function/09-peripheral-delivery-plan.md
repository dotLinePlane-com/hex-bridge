# HEX-Bridge 可选外设交付任务书

**起点**：HXB1 的 v1 配置事务、UART1/2、网络服务、DAP/SWD、外接 SPI2 和 SPI3 上的 MCP2518FD 已有实现。**第一项工作是 1.1。** 下列复选框记录本轮扩展工作；只有取得对应验收证据后才勾选。编号表示建议交付次序，不代表承诺日期。

需求与兼容边界见[设备功能清单](08-device-profile.md)、[配置协议](../protocol/17-Device-Profile.md)、[板级引脚表](../../sch/esp32-pinout-design.md)和[桌面工具设计](../../../tool/funcitonPinMap/design/DESIGN.md)。

## 应用端实施方案

保留 **Python + Tkinter/ttk 桌面应用和 Python CLI**。操作人员通过桌面配置，测试台和自动化通过 CLI 调用。两端共用配置读写、版本协商、文件校验和引脚占用计算。现有 GUI 已支持串口和 TCP、草稿与生效映射对照、异步 I/O、事务按钮及跨标签常驻引脚条。

| 层次 | 首批改动 | 交付结果 |
|---|---|---|
| 协议与配置文件 | 将 CLI 中的设备访问、编解码和三表计算提取成可正常导入的 Python 模块，保留原 CLI 入口及参数。分别处理 v1 和扩展描述。 | CLI 和 GUI 对同一报文输出相同的实例、通道和占用；现有 v1 命令及 JSON 文件继续可用。 |
| 设备会话 | 在现有 ProfileService 上扩展。保留硬件身份、源修订号、候选 ID 和草稿，串行执行设备操作。 | 同端口换板、旧修订、错误试用阶段和回包丢失均可识别；按设备读数恢复，保留未提交编辑。 |
| 配置界面 | 沿用顶部引脚条。下方以“功能 → 实例 → 通道/设备”选择编辑对象；开关、选脚和频率等通用字段复用表单。SPI 挂载、PWM 共享定时器和 RMII 路由采用专用控件。 | 描述中支持的项方可编辑。16 路 PWM 和 8 路 PCNT 以通道列表呈现，选择一行再编辑。每次只更新本地草稿，通过 CHECK 验证整份配置。 |
| 实际业务 | 配置页管理启停、映射和生命周期。各阶段另提供最小业务验证入口，例如 GPIO 读写、I²C 读寄存器、CAN 收发、PWM 输出或读取 PCNT 计数。 | 能验证某一配置既被保存，又能驱动对应外设。高频事件通过批量刷新显示；设备读写在工作线程执行，Tk 主线程更新控件。 |

第一版沿用现有分发方式和依赖。引脚条枚举设备板表中的全部可分配脚，绿色为空闲，蓝色为业务占用，红色为草稿冲突；当前、候选、草稿按各自快照计算。硬件通信遵循现有单会话约束。[Windows 桌面应用入口](../../../tool/funcitonPinMap/app.pyw) · [会话服务](../../../tool/funcitonPinMap/backend.py) · [Python Tkinter 线程模型](https://docs.python.org/3/library/tkinter.html#threading-model)

## 阶段 1 · 扩展配置基础，交付双 SPI 与现有外设

- [x] **1.1 固化基线和协议样例。** 从现有 v1 测试取出 DESCRIBE、READ、CHECK、SAVE 样例及一份非默认 JSON。完成扩展版能力发现、实例/通道 ID、总线引用、载荷长度、错误字段及超出单帧时的处理约定。交付协议文档与可执行样例；验收覆盖旧主机/新固件、新主机/旧固件和不支持版本三种组合，v1 的 11 字节映射保持原义。
- [x] **1.2 配置存储、整组校验与恢复。** 基于 1.1 扩展固件快照和事务。迁移原 CAN 的三条总线信号到 SPI3、CS/INT 到 MCP2518FD，外接 SPI2 恢复旧默认路由，沿用原开关和确认状态。用损坏、暂存、已开始试用、写入中断和重复请求做主机回归；旧客户端写入不得静默抹掉扩展字段。
- [x] **1.3 管理入口与试用保护。** 基于 1.2，要求 UART1 或“Wi-Fi STA + UBCP TCP 9500 + 已保存可用配网配置”至少满足一个；UART1 关闭仍保留 GPIO4/34。纯 Wi-Fi 管理时拒绝会删除唯一入口的 WIFI_FORGET；必要驱动初始化完成前拒绝 CONFIRM。验收覆盖禁用普通 TCP 仍可管理、错误入口确认、早确认、超时/驱动失败回退、有效确认后重启持久化。测试记录不包含本机配网凭据。
- [x] **1.4 双 SPI 固件与 MCP2518FD 挂载。** 基于 1.2、1.3，外接 SPI 业务和 MCP2518FD 各自选择 SPI2 或 SPI3。同主机共享一份总线映射、串行化事务，各设备保有独立时钟及 CS。验收覆盖重复 CS、关闭仍有依赖的主机、通用 SPI 尝试操作 CAN 专属 CS、换主机回退、GPIO15 仅供 MCP2518FD.CS。驱动申请、校验、引脚占用和释放使用同一套规则。
- [x] **1.5 共享 Python 模块与 CLI 联调。** 保留原 CLI 入口；通过 CLI 实际走通 v1/扩展版读取、JSON 导入导出、CHECK、SAVE、CANCEL、APPLY、CONFIRM 和超时回退。保存后对比当前与候选占用，验证表格与固件读数一致，记录可复跑命令及默认 SPI/CAN FD 业务结果，再进入 GUI 更新。
- [x] **1.6 更新并验收 Tkinter 应用。** 复用 1.5 已验证的协议与占用计算，按能力展示主机、线宽、信号映射和设备挂载；保留常驻引脚条及当前/候选/草稿视图。用 1.5 的同一组样例核对旧固件 9 脚和扩展 HXB1 的 15 脚、迁移试用与回退、修订冲突和同端口换板保护。GUI 验收属于阶段 1。

**阶段 1 引脚验收样例。** 扩展配置以总线允许的最大线宽决定资源预留。单线主机仅申请 SCLK、MOSI、MISO，外接设备另占 CS；Quad 配置额外申请 IO2/IO3，四根数据线均须双向。一次单线传输不会释放已为 Quad 预留的脚。若总线只配置为单线，运行时 Quad 请求应在访问 GPIO 前被拒绝。按默认接线且原有九个业务信号全开：外接 SPI2 单线时 13 占用、2 空闲（GPIO22/23），Quad 时 15 占用、0 空闲，仅关闭该外接业务及其无其他使用者的 SPI2 时 9 占用、6 空闲。旧版固件仍按原板表报告九脚；从 v1 迁移时须保留原有接线和 Quad 业务能力。

阶段 1.1–1.6 的实现、构建、主机回归、实板事务、恢复读回和待换线项目见[阶段 1 交付记录](../test-report/Stage1-Peripheral-Delivery.md)。复选框对应上述六项交付。下列阶段出口的物理接线覆盖另列。

**阶段出口**：在已确认接线下回归 UART、网络、DAP、通用 SPI 和 CAN FD 默认拓扑。在有相应接线的测试台上分别验证 MCP2518FD 挂 SPI2 和 SPI3 时的经典帧、FD 帧双向收发及 SPI 业务；记录实际接线、采集结果与恢复后的映射。原接线验证与迁移接线验证分项记录。

### 阶段 1 后续增量 · 双普通 SPI 通道与设备可选 CS

- [x] Profile v3 持久化与拓扑发现、旧配置迁移、共享 Python 编解码、占用预览及 Tk 能力门控。

## 阶段 2 · GPIO、双 I²C

阶段 2 评审材料按[功能设计](10-stage2-i2c-gpio.md)、[固件设计](../firmware/10-Stage2-I2C-GPIO.md)、[应用设计](../../../tool/funcitonPinMap/design/Stage2-I2C-GPIO.md)和[测试环境与验收矩阵](../test/10-Stage2-I2C-GPIO.md)组织。

以下任务沿用阶段 1 的协议、校验器和应用表单，每项均交付固件描述、驱动、CLI 业务操作、GUI 配置入口和测试。

- [ ] **2.1 GPIO。** 按脚选择输入、输出、开漏和中断，支持读、写及边沿事件。用回环线验证输出电平及输入事件；验证仅输入脚作输出、占用固定脚、与已启用业务重叠均被拒绝，关闭并生效后脚变为空闲。
- [ ] **2.2 I2C0/I2C1。** 两个实例独立配置 SCL/SDA 和速率，校验开漏能力和上拉条件，保留板载 EEPROM 的 GPIO12/33。用地址已知的器件验证两个实例分别收发、异脚并用、应答错误和恢复；关闭其中一路后验证另一路继续工作。GUI 按实例显示引脚及状态。

## 阶段 3 · PWM、计数和测量

- [ ] **3.1 LEDC PWM。** 依赖阶段 1 的通道描述与 GPIO 校验。提供 0–15 共 16 个可选通道，分配输出、速度组、定时器、频率、占空比与分辨率。主机覆盖首末通道、共享定时器冲突和引脚不足；实板用示波器或逻辑分析仪测量代表通道，记录设置值与实测值。16 是可选逻辑通道数，HXB1 的 15 个可改配脚限制了同时输出数量。
- [ ] **3.2 MCPWM。** 分组配置定时器、操作器、A/B 输出、死区，以及支持的故障/捕获输入。同组共享参数明确显示影响范围。先用逻辑分析仪验证互补波形、死区和停用输出，再验证故障输入动作。保持 LEDC 与 MCPWM 各自独立的资源诊断。
- [ ] **3.3 PCNT。** 提供 0–7 共 8 个可选计数单元，配置脉冲输入、可选控制输入和计数方式。输入已知数量脉冲，验证读取、清零、方向控制及停用；可用 3.1 的 PWM 或外部信号源。验证切换一个单元不会清空其他单元。

## 阶段 4 · 以太网

- [ ] **4.1 板型可行性。** 对照实际 PHY 型号、RMII 固定信号、参考时钟方向、MDC/MDIO、复位线及现有占用，产出逐脚接线和冲突表。存在无法解除的冲突时记录具体脚号与板型限制，当前板保持不可选；具备条件的板型进入 4.2。
- [ ] **4.2 驱动和上位机。** 增加以太网开关、板型路由选择、PHY/link/IP 状态。用真实 PHY 验证链路、地址获取、业务收发、拔插和恢复；以太网启用时仍执行 UART1 或 Wi-Fi 管理入口约束。GUI 分别显示配置启用、PHY 链路及 IP 状态。

## 阶段 5 · 片上经典 CAN（TWAI）

- [ ] **5.1 TWAI。** 增加片上经典 CAN 的 TX/RX、通道身份和收发命令，与 MCP2518FD 分别启停。使用收发器和总线对端验证经典帧双向收发，TWAI 拒绝 FD 帧；在 GPIO 足够时验证与外接 FD 控制器并用、两个实例的事件能正确区分。
