# 设备功能与引脚配置

**状态：阶段 1 的 v2 配置、双 SPI 路由、管理保护及共享 Python CLI/Tkinter 工具已实现；主机回归与实板验收分开记录。** v1 的 11 字节映射及旧主机事务保持兼容，v2 使用 26 字节映射。旧版实板曾验证保存、试用、超时回退、确认持久化及默认接线的经典 CAN/FD 收发；这些历史结果不替代 v2 双主机与迁移接线验证。报文见[设备配置协议](../protocol/17-Device-Profile.md)，本轮证据见[阶段 1 交付记录](../test-report/Stage1-Peripheral-Delivery.md)。

## 1. 用户可以配置什么

Profile v3 在 v2 的双主机路由上增加第二个普通设备通道和设备级可选 CS。SPI2、SPI3 可在关闭 CAN FD 时各自服务一个普通设备；无 CS 设备独占所在总线。桌面工具和 CLI 按设备能力开放配置。[双 SPI 验收记录](09-peripheral-delivery-plan.md#阶段-1-后续增量--双普通-spi-通道与设备可选-cs)

同一份 HEX-Bridge 固件可以适配不同接线和用途。用户通过现有 UBCP 连接查看完整引脚表，选择需要的功能，为板型允许改接的信号分配 GPIO。电脑控制串口等固定信号也显示在表中，便于核对接线。配置保存后重启生效，设备记住最后一次确认可用的配置。

例如，需要 UART2 和 CAN、无需 SWD 的用户，可以在一次修改中关闭 DAPLink，把 UART2 的 TX/RX 从 GPIO32/35 改到 GPIO25/26。设备接受整组修改后，上位机显示新接线。用户断开原有 SWD 接线，按新映射接入串口。再次开启 DAPLink 时，如果仍选择 GPIO25/26，设备应指出这两处冲突，让用户选择其他引脚。

## 外设功能管理路线图

下表是目标功能目录。启动配置以当前 HXB1 接线和已交付功能为基线。新驱动逐项加入，固件描述本构建支持的实例、通道数、信号约束和板级条件。上位机可同时展示规划项和已交付项；只有设备声明支持的项才提供配置入口。

| 可选功能 | 当前实现 | 目标配置及资源 |
|---|---|---|
| GPIO | 有协议设计 | 按脚启用数字输入、输出、开漏或中断。输入可选仅输入脚；输出、开漏须具备输出能力。 |
| SPI2、SPI3 | v2 已实现两主机分别启停；现有一个普通设备可选任一主机，默认外接 SPI2、CAN 使用 SPI3 | 两主机各自支持普通 SPI 收发，可同时使用并关闭 CAN FD。单线占 SCLK、MOSI/IO0、MISO/IO1，Quad 另占 IO2/IO3。普通设备独立选择 CS 或独占主机且不使用 CS；MCP2518FD 必须有专属 CS 和 INT。 |
| I2C0、I2C1 | 有 I²C 协议设计，板上有 EEPROM 接线 | 两个实例分别启停、配置 SCL/SDA 与速率；两脚均需双向开漏和外部上拉。通用实例从合法脚中选择，继续保护板载 EEPROM 的 GPIO12/33。 |
| UART1、UART2 | UART1 管理或普通串口（通道 2），UART2 业务（通道 1） | 各自可选。UART1 固定 TX4/RX34；UART2 允许改配 TX/RX。Wi-Fi UBCP 控制入口与普通 TCP 业务分别配置。 |
| 片上经典 CAN（TWAI） | 规划 | 独立启停，选择 TX、RX，需外接 CAN 收发器。 |
| 外接 CAN FD（MCP2518FD） | 已实现经典 CAN/FD，v2 可选 SPI2 或 SPI3 | 独立于 TWAI，默认选 SPI3；引用所选总线，单独配置 CS、INT。换控制器或引脚后须按新路由接线。 |
| LEDC PWM | 规划 | 最多 16 个逻辑通道逐路启停、分配输出 GPIO，配置频率、占空比和分辨率。检查高速/低速组及共享定时器的兼容性。 |
| 电机 PWM（MCPWM） | 规划 | 两组单元可选，按使用的定时器、操作器和 A/B 输出分配资源；互补输出、死区及可选故障或捕获输入单独校验。 |
| 脉冲计数（PCNT） | 规划 | 8 个计数单元逐路启停，各自配置脉冲输入、可选控制输入及计数方式，支持计数或编码器用途。 |
| 以太网 | 规划 | 可选片上 EMAC 与外部 PHY。板型声明可用的 RMII 数据线、参考时钟方案、管理线及可选复位脚，按固定路由和整组冲突校验。 |

**控制入口约束。** 每份候选必须保留 UART1，或保留 Wi-Fi STA 和 TCP 9500 管理服务且已有可恢复的配网参数。以太网、普通 TCP 业务、DAP 均不计作 Wi-Fi 控制入口。当前配置或确认回退配置仅靠 Wi-Fi 管理时，WIFI_FORGET 被拒绝且不清除凭据。切换入口须试用并从需要验证的入口确认；必要驱动及控制服务初始化完成前拒绝 CONFIRM，并拒绝过期会话。Wi-Fi 驱动初始化与取得 IP 分开判断，仍保留 UART1 时无需等待联网。

**总线与占用。** 控制器、总线信号、挂载设备分别建模。每个 SPI 主机只初始化一次，一组时钟/数据脚只计一次。共享同一主机须有兼容的总线映射、独立片选、串行化事务及独立设备参数；通用 SPI 的命令不得控制 CAN 的 CS。同一控制器的两套不同引脚配置、两个独立总线抢用同脚、关闭尚有启用设备的控制器均应在 CHECK/SAVE 报错。可在一次候选中迁移设备或关闭依赖方；关闭最后一个使用者且停用总线后才释放总线引脚。GPIO15 继续仅允许 MCP2518FD 的 CS。阶段 1 只能启用外置 MCP2518FD。阶段 5.1 的目标是在硬件和引脚满足两套配置时，允许 TWAI 与 MCP2518FD 分别启停或同时使用。

**交付次序（建议）。** 第一阶段保留已有 UART、Wi-Fi、DAP、外接 SPI2、MCP2518FD 业务和默认拓扑，先完成配置模型扩展、双 SPI 选择和旧配置迁移。第二阶段逐项加入 GPIO 和 I2C0/1。第三阶段加入 LEDC、电机 PWM、PCNT。第四阶段按具备对应 PHY 和布线的板型接入以太网。第五阶段加入片上经典 CAN（TWAI）。新增业务默认关闭。每项在发布前通过主机冲突测试、配置试用与回退，以及相应实板业务验证。16 路 PWM 和 8 路 PCNT 为可选通道上限；可同时使用的数量取决于引脚、共享硬件及当前配置。

**验收场景。** 覆盖两种 MCP2518FD 主机选择、共总线不同 CS、非法片选和总线迁移回退；校验两个 I²C 实例异脚并用、输入脚作输出被拒、PWM 定时器冲突、PCNT 单元重复、以太网缺少板级资源，以及关闭最后一个管理入口。固定保留、当前占用、候选预览继续分别从板表及生效/候选映射推导。每阶段仅公布已验证的设备能力。

v2 启用但无挂载设备的主机仍初始化并预留总线脚。最大线宽为 Quad 时，一次单线事务不释放 IO2/IO3；最大线宽仅单线时，运行时 Quad 请求在访问 GPIO 前被拒绝。外接 SPI 与已启用 MCP2518FD 共用主机时仅允许自动 CS，拒绝手动 CS 模式，避免长期选中设备阻塞 CAN。旧配置迁移保留外接 SPI2 的 Quad 路由，SPI3 启用继承原 CAN 开关。若配置含 v1 无法表达的路由或宽度，旧客户端的写入或事务变更被拒绝。

## 2. 已有功能与 v1 兼容基线

以下开关默认均开启，以复现 README 中的设备行为。“开启”表示允许使用，例如开启 UART2 后，主机仍按原协议打开串口。Wi-Fi 使用已有配网参数，网络服务在取得可用 IP 后工作。

| 功能开关 | ESP32 信号及出厂映射 | 关闭后的行为 |
|---|---|---|
| UBCP 串口控制 | UART1 TX=4、RX=34，板级固定 | 停止 UART1 控制传输；可另行启用 UART1 普通串口，GPIO4/34 始终保留 |
| UBCP 网络控制 | TCP 9500，无 GPIO | 关闭网络控制入口，UART1 可独立工作 |
| CAN / CAN FD | v1 为五个 CAN 信号；v2 为所选 SPI 总线及设备独立 CS/INT，默认 14/13/36/15/39 | 停止控制器访问、中断及事件，释放设备 CS/INT；v2 总线脚还须停用无其他依赖的主机才释放；经典 CAN 与 FD 共用开关 |
| 外接 UART | UART2 TX=32、RX=35 | 释放两脚，停止串口命令及收发事件 |
| Wi-Fi STA | 内置射频，无 GPIO | 停止联网与自动重连，保留已保存的网络参数 |
| TCP 业务 | 无 GPIO | 停止 UBCP 管理的 TCP 业务 |
| UDP 业务 | 无 GPIO | 停止 UBCP 管理的 UDP 业务 |
| WebSocket 业务 | 无 GPIO | 停止 UBCP 管理的 WebSocket 业务 |
| DAPLink 调试 | SWCLK=25、SWDIO=26 | 关闭 TCP 4441，释放 SWD 引脚；首期沿用无硬件复位线的接法 |

系统配置服务随设备启动。UART1/UART2 的外设编号、监听端口继续沿用现值。CAN 速率、UART 波特率、Wi-Fi 凭据等继续通过已有接口管理。自定义引脚只改变 ESP32 侧的信号路由，板载控制器若已固定布线，仍须满足实际电气连接。

v2 另提供两个 SPI 主机的启停、最大线宽和引脚，以及外接 SPI 业务的启停、主机和 CS。原 v1 描述仍将外接 SPI2 六脚列为固定资源；v2 将其纳入可配置池。I2C、通用 GPIO、批量传输和 OTA 尚未开放业务配置项。参见[中文 README](../../../README_zh.md)、[启动入口](../../../main/main.c)及[默认引脚定义](../../../main/hex_config.h)。

## 3. 引脚表与版本差异

### 三张引脚表及其写权限

| 上位机数据 | 回答的问题 | 来源与修改方式 |
|---|---|---|
| 系统固定引脚表 | 哪些 GPIO 永久专用，原因是什么？ | 固件编译时写死。显示 GPIO、系统用途或保留原因。运行程序、UBCP 命令、导入文件和 NVS 均无修改入口；关闭所属功能也继续保留。 |
| 可修改引脚表 | 每个业务信号允许选哪些 GPIO，目前配置了哪个？ | v1 为 UART2、CAN、SWD；v2 为 UART2、SWD、两个 SPI 主机及外接 SPI/MCP2518FD 的设备信号。关闭时仍保存映射。 |
| 当前占用表 | 哪个功能或系统用途现在占有这个 GPIO？ | 固件固定占用加上当前生效且已启用的业务映射，按 GPIO 列出占用方。它是只读结果；用户通过修改功能开关或信号映射改变业务占用。 |

一个 GPIO 可以同时出现在可修改表和占用表。例如 CAN 启用时，GPIO14 可以是候选输出脚，同时已被 CAN.SCK 占用。界面应显示占用方，允许用户在同一候选配置中将原信号迁走后再分配。占用表示该配置拥有引脚；CAN 通道尚未 OPEN、UART 空闲以及 SWD 暂时释放驱动都不会使引脚可被其他启用功能抢占。

| 当前板型的用途 | ESP32 引脚 | 配置界面与资源规则 |
|---|---|---|
| UART1（控制或普通串口） | TX GPIO4、RX GPIO34 | 显示两脚及方向，映射只读；串口关闭或 TCP 接管期间仍保留 |
| 烧录与日志串口 UART0 | TX GPIO1、RX GPIO3 | 映射只读，关闭日志输出后仍为下载接口保留 |
| 板内存储 | Flash GPIO6–11，PSRAM GPIO16/17 | 固定保留 |
| EEPROM 与外接 SPI2 | EEPROM GPIO12/33；默认 SPI2 GPIO18/19/21/22/23/27 | EEPROM 固定保留；SPI2 六脚仅在旧 v1 描述中固定，v2 按主机和设备配置计算占用 |
| 启动绑带保留 | GPIO0/2/5 | 固定保留，显示原因为启动绑带 |
| 用户可分配 GPIO | v1 九脚：GPIO13/14/25/26/32、仅输入的 GPIO35/36/39、仅限 MCP2518FD.CS 的 GPIO15；v2 增加 GPIO18/19/21/22/23/27，共 15 脚 | 按信号方向选择。原九条业务信号全开时，默认外接单线为 13 占用、GPIO22/23 空闲；Quad 为 15 占用；关闭外接业务及无依赖 SPI2 后为 9 占用 |

例如，在出厂配置上关闭 DAPLink，并将默认 CAN 总线的 SCK 从 GPIO14 改为 GPIO25。仅保存不改变当前占用；试用后 GPIO14 空闲、GPIO25 属于该总线，回退恢复旧占用。v1 占用方显示 CAN.SCK，v2 显示 SPI3.SCK。v2 关闭 CAN 仅释放设备 CS/INT，还须关闭无其他依赖的 SPI3 才释放总线信号；映射保留供编辑。GPIO15 始终仅允许 MCP2518FD.CS，实际接线须匹配所选路由。

板型表是固件校验的依据。配置导出可携带固定映射供核对；导入时相同映射按只读信息处理。试图更改固定信号、解除其锁定，或将其他信号分配到固定 GPIO，均须在预检和保存时拒绝整份修改。错误应能直接指导改线，例如“GPIO4 已固定用于 UART1.TX，请为 UART2.TX 选择其他引脚”。启动时也按当前板型重新校验持久化配置，旧配置中的映射不能覆盖固定值。

### 功能依赖与电气约束

- Wi-Fi STA 是 UBCP 网络控制、TCP、UDP、WebSocket 和 DAPLink 的共同依赖。这五个开关互相独立，例如只开启 Wi-Fi、DAPLink 和 UART1 控制时，仍可在 4441 调试。关闭 Wi-Fi 时，上位机列出需要一并关闭的功能，用户可一次提交；设备拒绝依赖不完整的候选配置，并列出涉及的开关。
- 至少保留一个 UBCP 控制入口。仅保留 TCP 9500 时，必须启用 Wi-Fi 并已有可用的配网参数；重启后仍需通过该入口确认连通性。两个入口均启用时，沿用单会话和 TCP 接管规则；仅启用网络控制时，断网后等待重连。
- 设备提供当前板型可分配 GPIO、方向能力、板级占用和启动绑带约束。TX、SCK、MOSI、CS、SWCLK 要求可输出；RX、MISO 要求可输入；INT 要求可输入并支持中断；SWDIO 要求可双向切换。GPIO34–39 只能用于板上实际引出且符合要求的输入角色，并提示外部偏置要求。
- 先保留板型表中的全部固定引脚，再为已启用的可配置信号检查冲突，每个 GPIO 只能分配一次。关闭可配置功能时保留上次映射供编辑。绑带脚按板型和信号角色许可，保留已知的默认 CAN CS=15 接法，并显示上电电平要求。
- 校验失败应包含功能、信号、GPIO、原因和占用方，例如“UART2.TX 无法使用 GPIO25，已分给 DAPLink.SWCLK”。一次返回全部已发现的问题；原配置继续工作。

## 4. 用户操作与失败恢复

| 步骤 | 用户操作 | 设备行为 |
|---|---|---|
| 查看 | 通过 UART1 或 TCP 9500 读取配置 | 返回板型、固件支持项、有效开关、当前引脚、可选引脚、确认版本及待应用状态 |
| 编辑和预检 | 修改一个或多个开关、引脚，查看差异 | 对完整候选配置做无副作用校验；主机可展示新旧控制入口及接线 |
| 保存 | 提交候选配置和读取时的版本 | 再次校验，保存完整候选，返回候选标识；版本过期时提示重新读取。保存后仍可取消或替换 |
| 应用 | 按差异提示准备接线，发起试用重启 | 先应答，再重启。旧连接中断，设备用候选配置启动；重复应用同一候选不会创建第二个版本 |
| 确认 | 用新配置连接设备，读取状态并确认候选标识 | 将试用版本标记为已确认并持久保存。控制入口有变时，应从变更后要验证的入口确认；CLI 提示用户先检查所需业务 |
| 恢复 | 新接线或网络无法连通 | 从试用启动起 120 秒内未确认，自动重启至上次确认版本；试用期间掉电、看门狗复位或必要驱动初始化失败也回退。主机显示旧接线和入口供重连 |

APPLY 先持久保存 ARMED，再发送响应。UART1 最多等待 500 ms 排空发送；TCP 管理会话关闭写方向，使响应后跟随有序 FIN，再最多等待 1500 ms 对端关闭并回收连接，随后重启。lwIP 的关闭重试另设 250 ms 发送超时，避免内存紧张时长期阻塞。等待中收到的后续载荷被丢弃，不作为确认或交付证明；断网或超时仍会启动已保存的试用。若主机丢失 APPLY 回包，应重连并 READ 阶段、候选 ID 和当前映射，区分等待重启、已试用、已确认或已回退，不能仅凭未收到响应判定保存失败。120 秒试用期限仍从候选启动开始计算。

120 秒为当前试用期限，仍需用实际 DHCP 和业务接线时间验收。仅配网中、CAN 总线空闲、UART 尚未 OPEN 或 SWD 未接目标均属正常等待状态。确认后的设备若日后因换网且仅保留 TCP 而失联，可通过固定的 UART0 下载接口单独清除 profile 分区，按出厂配置重新启用 UART1；保留其他 NVS 中的 Wi-Fi 参数及 UART1 速率。用户可从固定 GPIO4/34 重连。只擦除 profile 分区的地址与首次升级要求见配置协议。

## 5. 与现有固件和主机的衔接

- System 命令 0x08 提供描述、读取、校验、保存、取消、试用和确认操作。现有 GET_CONFIG/SET_CONFIG 的逐项语义和报文保持兼容。上位机通过 DESCRIBE 查询扩展支持情况。
- 配置按版本保存整份快照。独立存储区保留确认版本和候选版本，校验完整性后才切换启动记录。启动候选前先持久标记“已开始试用”，重启时看到未确认试用即回退。试用中禁止并发覆盖；对超时重发的保存、确认按候选标识返回已有结果。空配置使用现有默认值；损坏时优先使用有效确认版本，再回到出厂映射。存储不可写时保持有效配置并报告保存失败。
- 启动时先解析有效配置，再初始化模块、控制传输和网络监听。驱动的初始化、OPEN、重连、断开、GPIO 释放路径均使用同一映射。禁用模块不得在这些路径设置引脚、创建业务任务或监听端口；网络控制、DAPLink 与普通 TCP 业务分别检查各自开关。
- 区分固件支持、配置启用和运行状态。新查询能发现已关闭但可开启的功能；GET_INFO 中相关能力位、GET_TOPOLOGY 和通道数量按本次有效配置生成，沿用原有通道 ID。已关闭功能的直接命令返回约定的禁用错误。已启用但未联网、未打开通道等情况由运行状态解释。现有 GET_INFO 的硬编码掩码不能作为配置清单来源。参见[系统命令实现](../../../main/modules/mod_system.c)和[系统协议](../protocol/03-System.md)。

## 6. 首期验收

| 场景 | 验收结果 |
|---|---|
| 现有设备首次升级，无设备配置 | README 中的服务和引脚按默认值工作；已有 Wi-Fi 凭据和 UART1 速率仍可使用 |
| 逐一关闭、再开启各项功能 | 查询、命令响应、监听端口与开关一致；关闭的模块不操作原引脚；启用后可完成原业务 |
| 将 UART2 迁到已释放的 SWD 引脚 | 按示例接线可双向收发，旧引脚无 UART2 输出；重启后映射保持 |
| 查询、导出并导入本机配置 | UART0/1 显示固定映射、方向及用途；原样导入成功，改写只读映射或取消固定标记时整份配置被拒绝 |
| 关闭 UART1 后，将 UART2.TX 分配给 GPIO4；另测占用 UART0 的 GPIO1 | 两次提交均返回固定占用方；通过网络重新开启 UART1 后，仍可从 GPIO4/34 完成 PING |
| 启动时载入包含旧 UART1 改脚值的配置 | 拒绝不兼容快照，按恢复规则启动；UART1 启用时始终使用 GPIO4/34 |
| 分别改配 CAN 的 SCK、MOSI、MISO、CS、INT，按新映射接线；另测 SWD | 五个 CAN 信号均可从默认 GPIO 迁出，方向和中断能力校验正确；与对端完成经典帧、FD 帧收发；SWD 从新引脚读出目标 IDCODE |
| 按 GPIO14/25 示例查看暂存、试用和回退三个阶段 | 三张表在每个阶段均可区分系统保留、合法候选和实际配置占用；仅保存不改变占用，回退后旧占用恢复 |
| 重复分配、只输入脚作输出、v1 占用 SPI2 固定脚、v2 关闭仍有挂载的主机、缺少 Wi-Fi 依赖或关闭全部控制入口 | 预检与保存均报告具体冲突；当前会话和已确认配置不受影响 |
| 仅保留网络控制；另测仅关闭普通 TCP 业务 | 前者通过 9500 确认并可在掉线后重连；后者启用的 9500、4441 和 WebSocket 仍可独立使用 |
| 试用中接错线、超时、断电；保存中断或重复发起确认 | 设备启动到完整的确认版本或完整的待确认版本，状态可查询；未确认的试用按恢复规则回退 |
| 已确认的纯网络设备失去配网条件 | 通过 UART0 恢复默认功能映射后，能从默认 UART1 引脚连接，其他持久化参数保留 |
