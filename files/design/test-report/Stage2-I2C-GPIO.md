# 阶段 2 实板验收记录

测试对象为 HXB1（ESP32-D0WD-V3，MAC 28:56:2f:8f:82:88）与 NUCLEO-F103RB 双从机夹具。第二路时钟改接 GPIO13 后，两路主机在同一次实板验收中分别读到 A1 和 B2，双路并发与故障恢复通过。

| 用例 | 观测 |
|---|---|
| 固件与迁移 | ESP-IDF v6.0.2 烧录、读回哈希验证成功。包含恢复修复的镜像为 956848 字节，SHA-256 为 D93911B6A81F9F62DCCDA7C35537F9BE036EEE7646BAFE099EE72AE6D006612F。旧 v5 修订 165 升级后可逐字段读回。五项非法映射被设备拒绝；真实试用 120 秒后原映射恢复。 |
| GPIO | GPIO23→27、GPIO32→35 的电平、掩码原子拒绝、上升/下降沿、消抖、持续电平及两组事件隔离共 11/11 通过。 |
| I2C0 → A | 在 GPIO18/19 经 100/400 kHz 两档配置验证签名 A1、7 位扫描、RAM 写读、带寄存器前缀及 WRITE_READ、裸读和 10 位地址 0x250。速率为配置值。 |
| 超时恢复 | 初版在释放 SDA 后首读仍报 NACK。修复后 SDA 持低得到 TIMEOUT，释放后首笔读回 A1；另一次持低扫描期间 GPIO 回环和 PING 正常，独立用例连同夹具准备/收尾 4/4 通过。修复避免重发已经开始的写事务。 |
| I2C1 → A | 对调两控制器映射，让 I2C1 使用 GPIO18/19。两档速率、7/10 位地址、RAM、故障恢复及与另一条持低总线的并发共 8/8 通过；对端 A 在另一控制器超时前 0.609 秒返回。见[对调测试原始结果](stage2-swapped-controller.json)。 |
| 原第二组 → B | 初测通道 9 未读到 B2。逐线检查中 GPIO18、19、22 拉低/释放时 PB6、PB7、PB11 分别跟随；GPIO21 拉低和释放时，PB10 均读为低。 |
| 应用与回归 | CLI 和真实 Tk 应用都经 COM3@115200 与 TCP 9500 完成 A1 读取及 GPIO 高低回环。桌面套件 98 项、编译固件的 CLI/Tk 套件 21 项、协议样例 15 项通过；v1–v6 配置及实际 C 驱动模拟层回归通过。 |
| 电气测量 | 按用户要求跳过需要更换上拉电阻的用例。未使用分析仪测量 SCL 实际频率或上升时间。 |

更换跳线后，修订 180 下再次复测：第一组仍通过，第二组 100/400 kHz 均返回 TIMEOUT，从机 B 地址匹配计数仍为 0。随后单独将 I2C1 的 SCL 从 GPIO21 改为 GPIO13，修订 183 已确认并读回，无候选。时钟跳线移至 GPIO13 后，100 kHz 下两路分别读回 A1 01 00 00 和 B2 01 01 00。实板套件 27 项通过、0 项失败（I2C 16 项、GPIO 11 项），包含双路并发和故障恢复。两板分别供电且共地。测试结束后从机恢复 7 位地址，两路会话已关闭。当前保留修订 183。
