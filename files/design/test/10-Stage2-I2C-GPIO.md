# 阶段 2 测试环境与验收矩阵

状态为评审设计，以下均为待执行项。目标是分别证明配置可保存、两路 I²C 与多路 GPIO 能实际工作，以及失败后能够恢复。

## 环境与缺口

| 环境 | 需要准备 | 能验证的范围 |
|---|---|---|
| Windows 主机 | Python 3、pyserial、Tkinter；Visual Studio C 开发环境用于编译真实 C 配置/驱动配合模拟层；ESP-IDF v6.0.2、Xtensa 工具链、CMake、Ninja | v1–v6 数据和迁移、协议边界、错误注入、CLI、真实 Tk 控件、目标构建与分区容量 |
| HXB1 | 一块板、USB 下载及日志口、UBCP UART1 或已配网的 TCP 9500；验证管理切换需两种入口和 2.4 GHz AP | 烧录、配置试用/确认/回退、拓扑发现、断线重连 |
| 双 I²C 夹具 | 两个 3.3 V、地址已知的 7 位目标，支持 100/400 kHz 和有文档的寄存器，可设相同地址；也可用一块具有两套独立目标接口的可编程从机板。每条线有适当的外部上拉，短线、共地 | 两路异脚并用、同地址隔离、扫描、写读、重复起始、一路故障时另一路持续工作 |
| GPIO 夹具 | 两根回环线，开漏测试用外部上拉至 3.3 V，可切换的开漏下拉源。增加输入脚和回环对可同时验证两路边沿与串扰 | 输入、推挽、开漏释放、外部拉低、边沿/电平、批量掩码和事件隔离 |
| 完整覆盖 | 具备 10 位寻址及可控延迟/挂起的目标或仿真器，能释放 SDA 的开漏故障注入夹具。四通道 3.3 V 数字逻辑分析仪可同时采两组 SCL/SDA；400 kHz 总线建议至少 4 MS/s，常见 24 MS/s 档可用。测上升沿时间或电压裕量另配示波器 | 真实 10 位地址收发、超时恢复、波形中的 ACK/NACK 与 repeated START、两总线隔离的独立证据 |

评审时在本机确认 Python 3.11、Tk 8.6、pyserial 3.5 可导入，ESP-IDF v6.0.2 导出脚本存在。系统枚举到 COM3、COM5、COM6、COM7、COM9；本次未打开端口，端口用途需在试验开始时用板卡标识、PING/GET_INFO 确认。VS 开发环境与交叉工具链需在实施时实际编译核验。从设备型号、10 位目标、上拉、跳线和分析仪尚未现场确认。仅有主机和 HXB1 即可先做配置回归与 GPIO 跳线回环，双总线实测需两路真实应答。

## HXB1 候选接线

先导出已确认配置并记录 revision，断电拆除原 SPI 主从回环跳线及外设驱动。按实际映射停用或迁走与下表冲突的设备和主机，特别核对 SPI2、SPI3 片选。保留可用管理入口。该表是测试配置，工厂默认配置继续沿用原分配。

| HXB1 信号 | 接线示例 | 初始操作 |
|---|---|---|
| I2C0 | GPIO18 SCL、GPIO19 SDA → 目标 A | 100 kHz，读取已知寄存器 A |
| I2C1 | GPIO21 SCL、GPIO22 SDA → 目标 B | 400 kHz，读取已知寄存器 B |
| GPIO 路 0、1 | GPIO23 输出 → GPIO27 输入 | 先配置输入，再驱动低、高；开漏试验在该线上接外部上拉 |
| GPIO 高组（分轮） | 释放 UART2 后 GPIO32 输出 → GPIO35 输入；确认板上 UART 转接器已断开驱动 | 验证高组 bit 0 和 bit 3，并与低组同位号独立 |
| 公共参考 | HXB1、两个目标和仪器共地，SCL/SDA 各自上拉到 3.3 V | 可从每线 4.7 kΩ 起步，核实模块自带上拉的并联值和 400 kHz 上升时间 |

两路使用相同 7 位地址时可选择不同只读签名或预置不同的测试数据；寄存器写入选专用测试 RAM 或可恢复的测试区。普通 7 位 EEPROM 只能验证 7 位路径。开漏故障注入只在开漏模式接入，释放后再次读目标。板载 EEPROM 与 GPIO12/33 保持原接法。[板级接线](../../sch/esp32-pinout-design.md) · [乐鑫 I²C 电气说明](https://docs.espressif.com/projects/esp-idf/en/v6.0.2/esp32/api-reference/peripherals/i2c.html)

## 执行顺序与判据

| 顺序 | 用例与观测 | 通过条件 |
|---|---|---|
| 1 主机回归与构建 | 跑现有 test_profile_host、v2–v5、CLI 和 Tk 套件；新增 v6 字节样例、14 路边界、246 字节双快照、旧记录迁移、旧版写保护、NVS 写失败/断电模拟及双路队列测试。目标构建并检查镜像尺寸。 | 旧版本线格式和事务断言全过，失败事务保持原状态；合法请求长度与线上字节一致。 |
| 2 配置与回退 | 两路先后启停、同事务迁移 SPI 脚，提交脚号重复、输入脚作输出、固定脚被占等非法草稿；试用后分别确认、超时、断电重启。 | 占用和错误指向正确实例；合法候选可确认，失败或超时恢复原配置及管理口，旧业务通过回归。 |
| 3 I²C 实板 | 在两条总线上分别以 100/400 kHz 读签名，再交换速率。写测试寄存器、裸读、带前缀读、WRITE_READ、扫描、10 位目标，核对分析仪记录。 | 双向数据和目标期望一致，组合读之间无 STOP；扫描仅报告所在总线确认的地址。记录实际 SCL。 |
| 4 负例与并发 | A 缺失地址、持低 SDA 到超时、释放并重读；A 扫描/关闭期间向 B 发读请求；排队中断开 TCP 后新会话接管。 | NACK、超时状态可区分；B 在 A 超时完成前能返回其正确签名；旧事务不在新连接返回或重发。 |
| 5 GPIO 实板 | 两组各有一输出/输入，同组可另外临时将一根已释放的 I²C 脚改作输出。验证读写、多位掩码、方向错时整笔拒绝、开漏释放、上/下沿、消抖、电平持续和每脚限速。 | 选中位与分析仪一致，未选位保持；开漏释放后外部能拉低且可读回；事件标明正确路与时间，拥塞可见，低频路和控制仍响应。 |
| 6 应用与收尾 | CLI、Tk 分别经串口和 TCP 对照同一活动映射、数据与事件；保存再加载 JSON，试验中断线并重连。最后恢复试验前配置及接线。 | 候选和草稿不误当生效值；旧修订不会覆盖新配置；恢复后读回映射与起始导出一致，无测试候选。 |

GPIO 消抖和风暴用例可由另一 GPIO 的定时输出或外部信号源注入，按已知输入计数和周期与设备事件对照。每项记录板号、固件版本、Profile 修订、接线、命令/响应与波形；缺少指定夹具的项目列为待测。
